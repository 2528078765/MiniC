# MiniC 桌面端开发规范（PySide6）

> 版本：v1.0（草案）
> 状态：待实现验证
> 依据：`MiniC/web-ui` 界面原型（已确认）、`MiniC.md` 规格书（13 节 客户端形态与界面、5 节 关键技术决策、18 节 MVP）

## 1. 目标与原则

1. 桌面端是 MiniC 的**主界面**（规格书 18.1：实现顺序 CLI 先行，桌面端在 CLI 跑通后实现；CLI 已跑通，桌面端按此规范实现）。
2. **界面与交互以 `MiniC/web-ui` 原型为准**：原型里已确认的布局、组件、配色、交互反馈，桌面端逐一对应实现，不自行发明新样式。
3. 桌面端是**本地核心服务的客户端**：不直接读写 `.minic` 数据文件，所有操作走核心 API（`127.0.0.1` + Bearer 令牌），与 CLI 共享同一核心、同一数据、同一权限策略（规格书 3.1）。
4. 不做云同步、账号体系、三端互通（规格书 3.3）。

## 2. 技术选型

| 项 | 选择 | 说明 |
| --- | --- | --- |
| GUI 框架 | PySide6（Qt for Python） | 规格书 5 已确认；Win10/Win11 实测 |
| 网络 | httpx（同步为主，聊天/SSE 用流式） | 与 CLI 一致的 HTTP 客户端 |
| 主题 | QSS 深色主题，颜色集中定义 | 与 web-ui CSS 变量一一对应 |
| 打包 | PyInstaller（或 Nuitka）安装包 | 规格书 5：Win10/Win11 安装与卸载实测 |
| 数据流 | 全走核心 API | 不直接改 `.minic` |

## 3. 整体架构

```
┌─────────────────────────────────────────────┐
│ 窗口层（PySide6）                             │
│   MainWindow（主窗口）                        │
│   SettingsWindow（设置窗口）                  │
│   Dialogs（审批弹窗 / 配置弹窗 / 消息框）       │
├─────────────────────────────────────────────┤
│ 服务层                                        │
│   CoreClient（核心 API 封装）                  │
│     - 连接/鉴权（runtime.json 读端口与令牌）    │
│     - chat_stream（SSE 消费）                 │
│     - 线程/信号：QThread + Signal 异步不卡 UI  │
├─────────────────────────────────────────────┤
│ 本地核心服务（FastAPI，127.0.0.1）             │
│   与 CLI 共享：会话 / 记忆 / RAG / 工具 / 审批  │
└─────────────────────────────────────────────┘
```

1. **窗口层**只负责渲染与事件转发，不直接调 API。
2. **服务层**（`CoreClient`）统一封装 HTTP/SSE 调用，用 Qt 信号把结果抛回 UI 线程。
3. **启动流程**：启动时读 `~/.minic/runtime.json` → 无则提示"核心未运行"并提供启动（拉起 `minic serve` 或让用户启动）→ 有则连接并校验 `/health`。
4. **鉴权失效**：收到 `UNAUTHORIZED` 时重新读 `runtime.json`，必要时提示用户重启核心（规格书 4.2）。

## 4. 主窗口结构（对应 web-ui index.html）

布局用 `QSplitter`：左侧会话/项目栏 + 右侧对话区。

### 4.1 左侧边栏

| web-ui 元素 | PySide6 实现 | 行为 |
| --- | --- | --- |
| Z Logo | QLabel + 圆角样式 | 无交互 |
| 后退/前进 | QToolButton | 预留，可禁用 |
| 更新按钮 | QPushButton | 点击提示"已是最新版本" |
| 新建任务 / 搜索 / 技能 | QListWidget 或 QPushButton 列表 | 新建=新建会话；搜索=聚焦输入框；技能=跳设置-技能面板 |
| 项目区（标题 + ⋮⋮ ＋） | QLabel + 两个 QToolButton | ＋=新建项目（弹输入框）；⋮⋮=排序占位 |
| 项目/任务空状态 | QLabel（"还没有项目/任务"） | 新建后插入 QListWidgetItem |
| 底部设置入口 | QPushButton（"⚙ 设 置"全宽条） | 打开设置窗口 |

配色：侧栏 `#252526`，选中 `#37373d`，文字 `#ffffff/#cccccc/#858585`，强调天蓝 `#4fc3f7`。

### 4.2 顶部标题栏

1. 无边框窗口（`Qt.FramelessWindowHint`），自定义标题栏：左侧标题"当前工作区"（`📁 当前工作区`）、右侧窗口控制（最小化 `─` / 最大化·恢复 `□` / 关闭 `✕`）。
2. 窗口拖动：标题栏 `mousePressEvent/mouseMoveEvent` 实现。
3. 关闭按钮：确认后退出（或最小化到托盘，后续）。

### 4.3 对话区（欢迎页 + 对话流）

1. **欢迎页**（新会话初始态）：中央淡色大 Z（QLabel 透明度）、问候语（按时间切换）、大输入框（QTextEdit 单行高、带上下文栏"📁 当前工作区"、底部模型选择/质量/发送）、无快捷卡片、无提示条（原型已删）。
2. **对话流**（发送后切换）：居中容器（最大宽 900px），消息气泡：用户消息右对齐（背景 `#37373d`）、AI 消息左对齐（透明）。
3. **流式渲染**：消费 SSE `token` 事件，`QTextEdit`/`QLabel` 增量追加；`done` 事件带 `sources` 渲染来源块（文件路径 + 章节 + scope）。
4. **工具卡片**：`tool_call` 事件渲染卡片（工具名、参数、状态：完成/已拒绝/失败/需审批），折叠可展开（规格书 13）。
5. **模型选择**：点击循环切换（DeepSeek / Ollama / …），与核心 `GET /settings` 的 model 联动。

### 4.4 输入区

1. 大输入框：`QTextEdit`（回车发送、Shift+回车换行、自动增高限高）。
2. 发送按钮：天蓝圆角 `↑`。
3. 输入框下方不再有工具按钮（原型已删）。

## 5. 设置窗口结构（对应 web-ui settings.html）

1. 布局：`QSplitter` 左侧 `QListWidget`（导航）+ 右侧 `QStackedWidget`（面板）。
2. 导航项（全部为实体面板）：基础设置（常规/外观/模型设置/知识库）、Agent 能力（记忆/技能/子智能体/MCP 服务器）、数据与统计（使用统计）。**无插件、命令、钩子、索引库**（原型已删）。
3. 右上角固定窗口控制（`─ □ ✕`），与主窗口一致。

### 5.1 常规面板

1. 界面语言：`QComboBox`（系统默认/简体中文/English）。
2. 继承系统终端 Profile：`QCheckBox` 样式化为开关（开=天蓝）。
3. 终端字体：输入框 + 保存按钮。

### 5.2 外观面板

1. 主题：`QComboBox`（深色默认/浅色，可选实现）。

### 5.3 模型设置面板

1. 结构：左右分栏卡片。左=供应商列表（分组标题 + 供应商项 + 添加供应商），右=配置表单（名称 / Base URL / 模型 / API Key / 保存 / 测试连接）。
2. 供应商项：图标 + 名称 + 状态点（绿=正常），点击切换选中并预填表单。
3. "＋ 添加供应商"：新增条目并清空表单。
4. Base URL 输入框下提示"使用兼容 OpenAI 的 baseurl"。
5. 底部 Embedding 表单：Provider / 模型 / Base URL / API Key / 保存 / 测试连接，注明"仅全局配置（双库共享向量空间）"。
6. 保存 → 调 `PUT /settings`（全局 scope）；API Key 用密码框，说明"仅本地存储，不入库"。

### 5.4 知识库面板

1. **知识库路径卡片**："配置"按钮 → 弹窗（多目录模式）：
   - 输入框 + [选择目录]（`QFileDialog.getExistingDirectory`）+ [选择文件]（`getOpenFileName`）
   - "＋ 增加"：输入加入目录列表（可 ✕ 移除）
   - 保存（提交列表）/ 取消
2. **数据目录卡片**："配置"按钮 → 弹窗（单目录模式）：
   - 仅"全局"输入框 + 选择目录按钮（`getExistingDirectory`）
   - 项目目录**固定** `<项目>/.minic/rag-data`，不显示、不可配（说明文字提示）
3. 切分参数（chunk_size/chunk_overlap）、检索参数（top_k/vector/bm25）、启动自动入库开关保留（`QSpinBox`/`QDoubleSpinBox`/`QCheckBox`）。

### 5.5 记忆面板

1. 大输入框（`QPlainTextEdit`，等宽字体、可调高），预填全局长期记忆内容（`GET /memory?scope=global`）。
2. 右下角"保存"按钮 → `POST /memory`（mode=replace, scope=global）；内容空提示不保存。
3. 保存按钮放输入框下方右侧（避免与窗口控制重叠）。

### 5.6 技能面板

1. 标题 + 说明 + 右上角按钮（添加/导入/刷新）。
2. 搜索框 + 过滤下拉（全部/个人/Plugin）。
3. 分组："工作区与个人技能"（技能项：图标 + 名称 + 描述 + 个人标签 + 开关 + 删除）、"Plugin 技能"（名称 + 来源标签 + Plugin 标签，无开关）。
4. 数据来源 `GET /skills`；开关 → `POST /skills/{name}/enable|disable`。

### 5.7 子智能体面板

1. 标题 + 说明 + 右上角（新建/打开目录/刷新）。
2. 分组"内置子智能体"：卡片（锁图标 + 状态点、名称 + 内置标签 + 工具标签、描述、`built-in:xxx` ID、"继承默认 ▾"按钮）。
3. 数据来源 `GET /agents` 与内置 profile 静态展示。

### 5.8 MCP 面板

1. 与技能面板同结构：列出已配置服务器（`GET /mcp`）。
2. 服务器项：图标 + 名称 + transport/url 描述 + 状态标签（已连接绿/已禁用灰）+ 开关（对应 `disabled`）+ 删除。
3. 开关切换 → 更新配置（后续：`POST /mcp/{name}/connect`）。

### 5.9 使用统计面板

1. Tab（应用用量/模型用量）+ 时间范围下拉（近 7 天/近 30 天/全部）。
2. 活跃热力图：`QGridLayout` 小方块（GitHub 贡献图风格，颜色分级）。
3. 按天 Token 趋势：柱状图（`QPainter` 自绘或 QChart），底部日期轴；切换时间范围重新渲染。
4. 数据来源：核心记录统计（`GET /rag/status` 等扩展或后续统计接口）。

## 6. 交互规范

1. **点击反馈**：所有可点控件 hover/按下有视觉变化（QSS `:hover`/`pressed`），操作结果用 toast（右下角 `QLabel` 浮层，天蓝左边框，3 秒消失）或 `QMessageBox`。
2. **开关**：统一用 `QCheckBox` + QSS 样式化为胶囊开关（开=天蓝）。
3. **弹窗**：统一 `QDialog`（模态、遮罩可点击关闭），目录/文件选择用 `QFileDialog`。
4. **审批**：收到 `approval_requested` 事件 → 弹审批窗（显示工具名、参数、message），选项 允许一次/始终允许/拒绝（Bash 只允许一次/拒绝）→ `POST /threads/{id}/approve`（规格书 7、12.3）。
5. **发送消息**：回车或点发送 → `POST /chat/stream`（SSE 消费）→ 流式渲染 token、工具卡片、来源；`message_end(cancelled)` 停止渲染。
6. **设置保存**：配置面板修改后点"保存"才调核心 API 落盘（记忆、模型、知识库均如此），不实时写。

## 7. 数据流（GUI ↔ 核心 API 映射）

| 界面动作 | 核心 API |
| --- | --- |
| 启动连接/健康检查 | `GET /health` + 读 `~/.minic/runtime.json` |
| 发送消息/流式回答 | `POST /chat/stream`（SSE） |
| 审批提交 | `POST /threads/{id}/approve` |
| 会话列表/恢复/新建 | `GET /threads` / `POST /threads/{id}/resume` |
| 压缩/归档/删除会话 | `POST /threads/{id}/compress\|archive` / `DELETE /threads/{id}` |
| 长期记忆读/写 | `GET /memory` / `POST /memory` |
| RAG 入库/检索/状态/文档 | `POST /rag/ingest` / `GET /rag/query` / `GET /rag/status` / `GET /rag/documents`（scope 参数） |
| 工具执行（调试） | `POST /tools/run` |
| 设置读/写 | `GET /settings` / `PUT /settings` |
| 技能开关 | `GET /skills` / `POST /skills/{name}/enable\|disable` |
| MCP 状态 | `GET /mcp` |
| 子智能体 | `GET /agents` |

## 8. 工程规范

1. **目录结构**（新增 `src/minic/gui/`）：

```
src/minic/gui/
├── __init__.py
├── app.py              # QApplication 入口与主题加载
├── core_client.py      # CoreClient：API/SSE 封装 + 信号
├── theme.py            # QSS 深色主题与颜色常量（与 web-ui CSS 对齐）
├── main_window.py      # 主窗口（侧栏 + 标题栏 + 对话区）
├── settings_window.py  # 设置窗口（导航 + 面板栈）
├── widgets/            # 复用控件：toast / 开关 / 工具卡片 / 消息气泡 / 弹窗
│   ├── __init__.py
│   ├── toast.py
│   ├── toggle.py
│   ├── tool_card.py
│   ├── message_bubble.py
│   └── dialogs.py      # 审批弹窗 / 配置弹窗
└── panels/             # 设置面板
    ├── __init__.py
    ├── general_panel.py
    ├── appearance_panel.py
    ├── model_panel.py
    ├── knowledge_panel.py
    ├── memory_panel.py
    ├── skills_panel.py
    ├── subagents_panel.py
    ├── mcp_panel.py
    └── usage_panel.py
```

2. **命名**：类 `PascalCase`、方法/变量 `snake_case`；界面中文文案，代码标识英文。
3. **主题**：颜色集中在 `theme.py` 定义，与 web-ui CSS 变量一致（`--bg-main #1e1e1e`、`--bg-sidebar #252526`、`--bg-card #2b2b2b`、`--bg-active #37373d`、`--border #3c3c3c`、`--accent #4fc3f7`、`--text-*`）。
4. **线程**：所有网络调用放 `QThread`/`QRunnable`，通过 `Signal` 回 UI 线程；SSE 消费在后台线程，`token` 信号增量更新 UI。
5. **不引入额外 GUI 框架**：不用 QtWebEngine 嵌 web-ui（原生控件实现，符合规格书"独立原生桌面 GUI"）。

## 9. 测试与验收

1. **单元/控件测试**：pytest + `pytest-qt`（或 QtTest）覆盖关键控件与面板逻辑；网络层用 mock（复用现有 mock provider/fixture 模式，CI 不依赖真实 API）。
2. **手动验收清单**（对照 web-ui 原型逐项）：
   1. 主窗口：侧栏/标题栏/欢迎页/对话流/输入区布局与原型一致。
   2. 发送消息流式显示，工具卡片、审批弹窗（允许一次/始终允许/拒绝）、来源块正常。
   3. 设置各面板：常规/外观/模型设置（供应商管理 + Embedding 表单）/知识库（两种配置弹窗）/记忆（大输入框 + 保存）/技能/MCP/子智能体/使用统计，交互与原型一致。
   4. 设置保存后核心数据生效（`GET /settings`、`/memory` 可验证）；API Key 不明文入库。
   5. 双库 RAG：检索结果带 scope，知识库配置弹窗按双库策略。
   6. 崩溃恢复：核心重启后 GUI 提示、会话消息不丢（复用现有机制）。
3. **打包验收**：安装包在 Win10/Win11 安装、卸载、启动、核心自启（或引导）实测。
